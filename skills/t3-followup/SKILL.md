# Follow-up selection for T3 Antigravity

The user has opted into choosing one workflow for each interactive T3 request. Explicit instructions, a stop request, a named or existing verification workflow and any limits on tools or delegation take precedence. Use this policy only in an interactive T3 chat.

When project QA requires a fresh reviewer to exercise a changed user flow, use a fresh session from the same model family by default and save `REVIEW.md` before merge. Keep the normal QA handoff. Visual critique cannot satisfy this behavior check. The hands-on review covers the completion review of the same final change. Recheck affected behavior after further edits.

- **Direct answer.** Finish simple questions, status checks and mechanical edits directly. For requested titles, summaries and other constrained text generation, return the requested text.
- **Visual design.** Handle routine design or polish directly. The original builder uses the rubric from the brief (or its audience and task) on renders at the target sizes (desktop and phone for responsive work), names the screen, visible weakness and reader impact, revises once if needed, and verifies. A self-score is optional. In a top-level T3 user chat choosing among finished directions for a flagship screen or redesign, use the council skill’s blind finished-design comparison directly. For a requested second opinion or one material visual question still unresolved, send the brief, renders and question to one read-only reviewer from a different model family when available. The original builder decides and edits. Count visual advice only when the reviewer saw the renders and cites a visible detail tied to the brief. Disclose missing image access. Finish this design route without a duplicate completion review.
- **Council for scoping.** For a large change with an open decision that would materially alter the scope or approach, use council before choosing a plan or implementing it. For example, two credible redesigns would change different user flows. Only the top-level interactive T3 agent with `delegate_task` takes this path. Read the council skill at `~/.claude/skills/council/SKILL.md` and follow its planning rounds with the configured seats. Use the result for the authorized work. This choice needs no completion review or adaptive follow-through. A settled rollout, a large mechanical edit, or a discussion about council routing does not trigger it.
- **Completion review.** For a bounded deliverable that needs source reconciliation or a real behavior check, do the work first. Before handing it back, ask one fresh reviewer on the current provider to check the original request against the actual artifact and relevant evidence. Give the reviewer a read-only brief, with only the context it needs. Follow the native or T3 delegation contract for the current chat. A fresh review of the requested artifact and its source evidence also covers the handoff summarizing that verdict. Correct any material gap that falls within the request and verify the correction. If independent review is unavailable, say which evidence you checked yourself.
- **Adaptive follow-through.** When later steps depend on what you find, finish the next authorized step, inspect the result, and repeat until you have verified the requested outcome or reached a genuine blocker. Use the current ACP task. Respect a user-specified step limit, and stop when the user pauses or changes direction.

Generated next steps inherit the original permissions. Keep decisions, account changes, and external actions within what the user authorized.
