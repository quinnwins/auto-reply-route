# Automatic follow-up in T3 Code

The active model chooses a direct answer for simple requests, a fresh independent
review for a deliverable with evidence to check, or adaptive follow-through when
the next step depends on what it finds. Explicit user instructions and limits
take precedence.

Each T3 driver loads its own configuration. Keep the following files available to
the corresponding runtime.

| Provider | Configuration and behavior |
| --- | --- |
| Codex | Register the [Codex handler](../scripts/codex_followup.py) on `UserPromptSubmit` and `Stop`. Review both definitions in the native Hooks menu for the exact Codex home in use. A selected review resumes the current turn. The adaptive path uses the installed `/g` skill. [Codex setup](CODEX.md#optional-automatic-follow-up-selection) |
| Claude Code | Register the [Claude handler](../scripts/claude_followup.py) on `UserPromptSubmit` and `Stop` alongside the existing Claude `/g` hook. On installations that regenerate profile settings, add the entries to the generator's source and limit them to the intended T3 homes. The handler binds a selected review to the Claude session and prompt. Automatically selected `/g` runs finish quietly. |
| Grok | Load the [Grok rule](../rules/grok-followup.md) from `~/.grok/rules/`. Make the [handler](../scripts/grok_followup.py) available at `~/.grok/hooks/grok_followup.py` and register it for `UserPromptSubmit`, `Stop`, `StopFailure` and `StopCancelled`. When the running Grok session loads these hooks, the native Stop can request one review or up to four adaptive continuations. When the session withholds hooks, the rule asks the model to seek the review within the current turn. Interactive trust and headless ACP discovery can differ. |
| Antigravity Ultra | Make the [T3 follow-up skill](../skills/t3-followup/SKILL.md) available in the user skills directory linked to the T3 ACP profile. The model can choose the workflow during the turn. The managed ACP 1.1.1 runtime ignores hook requests to continue at Stop. Skill discovery alone does not establish that a reviewer ran. |

Reviewers receive the original request and the evidence necessary to check it.
Adaptive steps stay within the user's authorized scope. For a particular result,
the reviewer's recorded activity and the delivered artifact establish what ran.
